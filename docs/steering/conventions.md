# Conventions Steering

## General Code Style

- [Decision] Write TypeScript in strict mode.
- [Decision] Prefer small, typed functions for image math, filename mapping, MIME mapping, and settings validation.
- [Decision] Keep Angular components focused on UI state and event handling.
- [Decision] Keep processing algorithms in services, core modules, workers, or pure utilities.
- [Decision] Avoid adding compatibility layers unless there is a concrete browser or persistence need.

## Angular Conventions

- [Decision] Use standalone components.
- [Decision] Use route-level lazy loading for tool workspaces where practical.
- [Decision] Use Signals for local reactive state.
- [Decision] Avoid NgRx.
- [Decision] Prefer `OnPush`-compatible patterns and immutable state updates.
- [Decision] Use modern Angular template control flow when available in Angular 21.
- [Decision] Keep forms simple unless Signal Forms becomes stable and intentionally adopted.

## File Naming

- [Decision] Angular component files use kebab-case feature names.
- [Decision] Models end with `.model.ts`.
- [Decision] Services end with `.service.ts`.
- [Decision] Pure utilities use descriptive kebab-case names, such as `size-format.ts`.
- [Decision] Worker files should be clearly named with `.worker.ts` when generated by Angular tooling.

## UI Conventions

- [Verified] Tool cards include icon, name, and one-line description.
- [Verified] Workspaces include upload zone, controls, preview/results, and download.
- [Verified] Output options are collapsed by default.
- [Decision] Keep primary task controls above advanced codec options.
- [Decision] Show before size, after size, and savings whenever a tool changes file size.
- [Decision] Make browser capability limitations visible instead of pretending unsupported options work.

## Processing Conventions

- [Decision] Never upload files for processing.
- [Decision] Use Blob outputs with explicit MIME type and filename.
- [Decision] Preserve source dimensions unless the selected tool changes dimensions.
- [Decision] Encode format support must be feature-detected where browser support varies.
- [Decision] Return structured warnings for unsupported or partially supported settings.

## Documentation Conventions

- [Decision] Use `[Verified]`, `[Decision]`, `[Inferred]`, and `[Unknown]` markers in steering docs.
- [Decision] Keep feature specs under `docs/specs/<number>-<feature>/`.
- [Decision] Use `tasks.md` dependency markers to sequence implementation.
